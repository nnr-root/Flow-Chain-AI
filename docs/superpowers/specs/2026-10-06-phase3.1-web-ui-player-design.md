# Phase 3.1 — Web UI and Remotion Player — Design

Date: 2026-10-06 · Status: approved (sections 1–4), prototype pending · Builds on Phase 2.4 (`b1b179d`)

## 1. Goal

A local, single-user web application ("the studio") on top of the existing pipeline: create a video from a
form, preview it in the browser with the Remotion Player before and after the paid media is bought, change its
look live, and trigger every pipeline action with the cost shown first and capped.

The pipeline engine, its cache keys and the CLI's behaviour do not change. The studio is a second front end to
the same runs.

### Non-goals (later sub-projects)

Accounts, a database, a job queue, cloud storage, billing, hosting, more than one user; editing the script or a
timeline by hand; changing a run's frozen choices (aspect, provider, seed, characters) after creation.

## 2. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Next.js App Router app in `web/`, an npm workspace of this repo | shares `src/` instead of copying it; the CLI keeps working alone |
| D2 | The Player mounts the same `Video` component with the same `RenderProps` as the render | no second implementation, so no visual drift |
| D3 | A **draft is a run** whose pipeline stopped after the `script` stage | one data model; the script bought for the draft is the one the run uses; everything frozen per run is frozen by the existing code |
| D4 | Writes spawn the CLI as a **detached child process**; the manifest stays the source of truth | the live-verified code path; a paid job survives a web-server reload; Next never bundles the renderer or ffmpeg |
| D5 | Reads use a narrow pure module (`src/studio/`) | cheap, typed, no heavy imports; the same functions the stages use |
| D6 | One seam in the composition: a media-URL resolver that defaults to `staticFile` | the render path is unchanged; the browser maps the same props to URLs |
| D7 | Every paid action is approved for an amount, passed to the CLI as its budget without `--yes` | the CLI aborts (exit 2) instead of spending more than the user saw |
| D8 | Per-scene mode overrides are a new optional request field, settable only on a draft | modes are frozen with what is bought |
| D9 | The server listens on `127.0.0.1` and refuses cross-site writes | there is no login in 3.1, and a web page must not be able to spend money through `localhost` |

## 3. Architecture

```
browser ── pages (server components) ── src/studio (pure reads) ── runs/<id>/manifest.json
   │                                                                     ▲
   ├── Player (client) ── GET /api/runs/<id>/files/… ── files module     │ writes
   │                                                                     │
   └── actions ── POST /api/… ── jobs module ── spawn `flowchain …` ─────┘
```

### 3.1 Layout

```
web/
  app/                    pages and route handlers (App Router)
  components/             client components (Player, forms, panels)
  server/                 runs.ts, jobs.ts, files.ts, brand-kits.ts, http.ts (errors, same-origin guard)
  test/                   vitest (server modules, route handlers) and Playwright (one flow)
src/studio/               pure read functions shared by the CLI's --json commands and the web server
src/media/remotion/       the composition; gains media.tsx (the resolver context)
brand-kits/               kits created in the studio (git-ignored)
uploads/music/            music uploaded in the studio (git-ignored)
```

`web/` depends on `next`, `@remotion/player` **4.0.532** (the same exact version as every other Remotion
package), `react`/`react-dom` **19.3.0**, Tailwind CSS, Radix primitives, React Hook Form and `zod`. React and
Remotion are hoisted to one copy for the whole repo.

### 3.2 `src/studio/` (pure reads)

| Function | Returns |
|---|---|
| `runSummary(m, job)` / `listRuns(runsDir)` | id, topic, created, state, spend, thumbnail path |
| `statusOf(m)` | the structured form of what `formatStatus` prints (`formatStatus` is rebuilt on it; its text does not change) |
| `previewProps(m, opts, captions, flags?)` | `{ props, files }` for a run with media: `applyRenderOptions` on a copy, then `buildRenderProps` |
| `buildDraftProps(m, opts)` | `{ props, files }` for a run that has only a script (§5.2) |
| `draftEstimate(m, …)` | provisional per-scene modes and the estimated total (§6.2) |

Nothing in `src/studio/` imports the Remotion renderer, the bundler, ffmpeg wrappers or a provider SDK.

### 3.3 Run states (derived, never stored)

| State | Meaning |
|---|---|
| `creating` | the run folder exists with a job but no manifest yet |
| `draft` | `script` is done, no media stage has a record, no active job |
| `running` | a job is alive |
| `needs_approval` | the last job ended with exit code 2: the plan exceeded the approved amount |
| `failed` | a stage record is `failed`, or the last job ended with another non-zero exit code |
| `interrupted` | a job is recorded as started but its process is gone and it recorded no end |
| `done` | `final` exists and the last job, if any, ended with 0 |

## 4. Jobs (`web/server/jobs.ts`)

- **Start.** Spawns `node <repo>/node_modules/.bin/tsx src/cli.ts <args>` detached with `cwd` = repo root,
  stdout and stderr appended to `runs/<id>/job.log`, and writes `runs/<id>/job.json`:
  `{ id, kind, args, pid, startedAt, approvedUsd, endedAt?, exitCode? }`. The CLI binary is taken from
  `FLOWCHAIN_CLI` when set (tests point it at a stub).
- **One per run.** A live job, or the pipeline's own `.lock`, makes a second action fail with `409 job_active`.
- **Machine limit.** At most `STUDIO_MAX_JOBS` (default 2) live jobs; further starts fail with `429 busy`.
- **End.** While the web server lives, the child's exit writes `endedAt`/`exitCode`. After a web-server restart
  a job whose pid is still alive is `running` (its end is then inferred from the pid disappearing and the
  manifest: `exitCode` unknown → `interrupted` unless the manifest shows the work finished).
- **Stop.** `DELETE …/job` sends `SIGTERM`; the CLI already removes its lock on that signal, and any submitted
  provider request stays recorded, so a resume continues without buying twice.

| Action | CLI |
|---|---|
| create draft | `run --draft --run-id <id> --mode auto --budget <modeBudget> …form flags…` |
| set scene modes | `draft-modes <id> --modes auto,1,2,auto` (synchronous, free) |
| generate / resume | `resume <id> --budget <approvedUsd>` |
| reroll | `reroll <id> --scene <n> --stage <s> --budget <approvedUsd>` |
| re-render | `rerender <id> …look flags…` |
| price an action | `plan <id> --json [--reroll <n>:<stage>] [--modes …]` (synchronous, free) |

## 5. The Player

### 5.1 The media seam

`src/media/remotion/media.tsx` exports `MediaProvider` and `useMedia()`: a context holding
`(publishedPath: string) => string`, default `staticFile`. `SceneLayer`, `AudioLayer`, `BrandLayer` and
`Captions` (font loading) call `useMedia()` instead of `staticFile` directly. The render bundle passes no
provider, so its output is unchanged; the existing Chrome render tests are the guard.

In the browser the resolver is `(p) => /api/runs/<id>/files/<p>`. The files route serves **only** the published
paths in the `files` map that the same `previewProps`/`buildDraftProps` call returns (plus `final.mp4`,
`chain.png` and keyframes for thumbnails), with `Range` support. A music file or bundled font outside the run
folder is therefore reachable only because the run's props name it.

### 5.2 Draft props

`buildDraftProps` returns a valid `RenderProps` from a manifest with a script and no media:

| Part | Draft value |
|---|---|
| scene length | estimated from the narration (constant calibrated in the prototype from the existing runs), then `sceneFrameCounts` |
| scenes | all `still`, `src` = `draft/scene_NN.svg`: a generated card with the scene number, shot, provisional mode and visual prompt; camera move from the script |
| boundaries, transitions | real, from the script, the render options and the provisional modes |
| captions | the real words in the real style; word timings spread across the estimated length by word length, then the same `wordsToCaptions` and `captionPages` |
| hook, brand, music, sound effects | real |
| narration | `draft/silence.wav`, generated to the estimated length |

`draft/…` paths are virtual: the files route generates them. `buildRenderProps` and `buildDraftProps` share one
assembly function so the two cannot diverge; `buildRenderProps`' output stays identical (its tests are the guard).

### 5.3 Live look changes

The studio holds pending look changes as `RerenderFlags`. Each change posts them to the props route; the server
answers with `previewProps(m, …, flags)` and the Player swaps its `inputProps`, keeping the frame. "Apply" runs
`rerender` with the same flags. Preview and render call the same two functions with the same flags.

A brand kit applied in preview only is served from `brand-kits/<slug>/`; "Apply" installs it into the run as
`rerender --brand` does today.

### 5.4 Limits

Browser playback is not frame-exact and heavy transitions may stutter; the rendered MP4 is unaffected. Draft
timings are estimates. Remotion's licence is free for individuals and companies of up to three people; larger
for-profit companies need a company licence (not legal advice — check before launch).

## 6. Forms and Panels

### 6.1 New video (`/new`)

One zod schema (`web/server/schemas.ts`, built from `Aspect`, `PresetName`, `CaptionStyleName`, `Transition`
and the limits in `RunRequest`/`RenderOptions`) validates in the browser and on the server.

Fields: topic; aspect; scenes (1–12); style preset (card grid plus "let Gemini choose"); motion (auto / all
clips / all stills — the starting position of the per-scene switches); provider (fal / RunPod, default
`PROVIDER_MODE`); budget for the run's mode rules (default `FLOWCHAIN_BUDGET_USD`); brand kit; music (bundled
or uploaded MP3) and level; advanced: hook text or no hook, sound effects and level, characters, seed, voice
id, caption style, transition at cuts.

`GET /api/health` reports which keys are present (no network calls); the form refuses a provider whose keys are
missing, naming the variables.

### 6.2 Per-scene modes on a draft

- `RunRequest.modeOverrides?: Array<1 | 2 | null>` (optional; absent on every existing run and on CLI runs).
- `planModes` takes `pinned`: a pinned scene starts at its pinned mode and is never downgraded; its reason is
  `set by you`. The modes stage passes `pinned` only when overrides exist, so every existing run's `modes` cache
  key is unchanged (`stableStringify` drops `undefined`).
- `draft-modes` writes the overrides and each scene's **provisional** mode (`draftEstimate`: `planModes` on
  estimated clip lengths), so the plan the CLI prices before the audio exists matches what the user saw. The
  modes stage still makes the final decision once the audio exists. It refuses when any `tts`, `keyframes` or
  `clips` record or ledger entry exists.
- The studio always creates auto runs; "all clips" and "all stills" are overrides on every scene.

### 6.3 Brand kits

A kit is still a folder with `brand.json`. `POST /api/brand-kits` (multipart) stores files under
`brand-kits/<slug>/` (slug from the name; file names are generated, never taken from the upload), writes
`brand.json` and runs `loadBrandKit` on it; on failure the folder is removed. Limits: logo PNG/SVG ≤ 2 MB, font
TTF/OTF ≤ 5 MB, portrait PNG/JPG within `installReference`'s existing limit. SVGs are served with
`Content-Security-Policy: sandbox` and are only ever used as images. The kit form shows a small Player with a
sample scene.

### 6.4 Studio (`/runs/[id]`)

Player with a scene strip (one block per scene: shot, mode, action level; click seeks); look controls (caption
style, transition, hook, sound effects, music level, brand) with Apply and Reset; cost panel (estimate for the
next action, recorded spend, ledger by stage, "estimates from the price table, not invoices"); progress panel
(the `statusOf` grid, live); per-scene actions (new voice take, keyframe, clip; new portrait where one exists),
each priced first.

## 7. API

Errors: `{ error: { code, message, hint? } }`. Mutating routes require `Content-Type: application/json` (or
multipart for uploads) **and** a same-origin request (`Sec-Fetch-Site: same-origin`, or an `Origin` whose host
is the request's host); the server also rejects a `Host` that is not a loopback name.

| Route | Does | Notes |
|---|---|---|
| `GET /api/health` | which providers are usable | no network |
| `GET /api/runs` | list | newest first |
| `GET /api/runs/[id]` | `statusOf` + state + job | |
| `POST /api/runs/[id]/props` | Player props, optional `flags` | validated against `RenderProps` before sending; `draft: true` for a draft |
| `GET /api/runs/[id]/files/[...path]` | media | only published paths; `Range` |
| `GET /api/runs/[id]/events` | server-sent events | `status` on manifest change, `log` lines, `job` end, heartbeat |
| `POST /api/drafts` | create a draft | `202 { runId }` |
| `POST /api/runs/[id]/modes` | set overrides on a draft | returns the new estimate |
| `POST /api/runs/[id]/plan` | price an action | `{ items, totalUsd }` |
| `POST /api/runs/[id]/generate` `/reroll` `/rerender` | start a job | `approvedUsd` required for paid actions; `202 { job }` |
| `DELETE /api/runs/[id]/job` | stop | |
| `GET`, `POST /api/brand-kits` | list, create | |
| `GET /api/music`, `POST /api/music` | list, upload | MP3 ≤ 20 MB |

Error codes: `validation`, `not_found`, `job_active`, `busy`, `estimate_changed` (the plan now exceeds
`approvedUsd`; carries the new total), `not_draft`, `missing_keys`, `forbidden_origin`.

## 8. CLI additions (no existing behaviour changes)

| Addition | Behaviour |
|---|---|
| `run --draft` | runs only the `script` stage, then prints the status; `resume` continues the run |
| `run --run-id <id>` | uses this id (must match the run-id format and not exist) instead of a new one |
| `draft-modes <id> --modes <list>` | §6.2 |
| `plan <id> --json` (+ `--from`, `--reroll n:stage`, `--modes`) | prints `{ items, totalUsd }` from `planRun`; changes nothing on disk |
| `status <id> --json` | prints `statusOf` |
| `reroll --budget <usd>` | with it, a reroll is capped like a resume instead of always asking |

Exit codes stay: 0 done, 1 failed, 2 not confirmed (`RunAborted`).

## 9. Compatibility

Existing runs gain no field and no stage. `modeOverrides` is optional and absent on them; `pinned` is passed
only when overrides exist. `buildRenderProps` and `formatStatus` keep their exact output.
`test/unit/compat.test.ts` stays untouched. A run made by the studio is an ordinary run: the CLI can resume,
reroll, re-render and show it.

## 10. Failure handling

| What happens | Result |
|---|---|
| plan exceeds the approved amount, before or at the media checkpoint | job ends with exit 2 → `needs_approval`; the UI shows the new estimate and asks again; nothing beyond what was already approved is bought |
| provider job fails or times out | `failed`; the step, its error and the recorded charge are shown with the pipeline's own advice (resume / reroll) |
| Stop | `SIGTERM`; resumable |
| web server restarts mid-job | the job keeps running; the server finds it again from `job.json` |
| hard kill leaves `.lock` behind | `interrupted`, with a "clear the stale lock" action that only works when the recorded pid is dead |
| missing keys | the form refuses before a draft exists |
| a file the Player needs is missing | the scene shows an inline error; the studio keeps working |

## 11. Testing

No test spends money: `FLOWCHAIN_CLI` points at a stub script that records its arguments and edits a fixture
manifest.

- **`src/` unit tests:** `buildDraftProps` validates against `RenderProps` and is deterministic; `previewProps`
  with flags equals `buildRenderProps` after `applyRenderOptions`; `planModes` with `pinned`; `draft-modes`
  rules; `statusOf` ↔ `formatStatus`; `run --draft` stops after the script; `reroll --budget`; the media
  resolver default.
- **`web/` unit tests (vitest, node):** schemas against the CLI's enums; jobs (spawn, lock, limit, end,
  restart detection, stop) against the stub; files (confinement, virtual draft files, ranges); brand-kit and
  music uploads; the same-origin guard; every route handler with a fixture run folder and each error code.
- **Browser (Playwright, one flow)** on a fixture run with real small media: list → studio → the Player mounts
  and its frame advances → change the caption style → new props arrive → Apply starts a `rerender` job on the stub.
- **Existing suites:** 330 vitest and 41 pytest tests still pass.
- **Live check (paid, needs approval):** one draft, per-scene mode change, one generated video through the UI
  on RunPod (≈ $0.27), one free re-render; recorded in this spec.

## 12. Definition of Done

1. `npm run web` starts the studio on `127.0.0.1`.
2. A draft can be created, previewed, adjusted per scene and generated from the browser.
3. A finished run plays in the Player, look changes preview live, and Apply produces a matching MP4.
4. Brand kits and music can be uploaded and used.
5. Every paid action shows its estimate first and cannot exceed it.
6. All tests in §11 pass; the README covers the studio; the live check is recorded here.

## 13. Risks and Unknowns (the prototype answers the first three)

- Whether Next's bundler resolves this repo's `.js`-suffixed TypeScript imports for both the server (`src/studio`)
  and the client (the composition) without changing `src/`.
- Whether the composition, written for a render bundle (`OffthreadVideo`, `delayRender` font loading), behaves
  in the Player unchanged apart from the resolver.
- Which Next.js version works with React 19.3.0 and Remotion 4.0.532 as pinned.
- Draft timing error against real voiceovers (calibrated on four existing runs only).
- Browser decode load with four 1080 × 1920 clips and a blur transition on a laptop.
