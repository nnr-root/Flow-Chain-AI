# Phase 2.1 — Remotion Render Engine: Design Spec

- **Date:** 2026-10-03
- **Status:** Approved (brainstorming sections 1–4)
- **Scope:** Sub-project 2.1 of Phase 2. Sub-projects 2.2 (content intelligence & style presets) and 2.3
  (hook, auto-SFX, brand kit) get their own spec → plan cycles and build on this engine.
- **Builds on:** `docs/superpowers/specs/2026-10-02-phase1-cli-poc-design.md` (Phase 1, verified live:
  continuity chain seams measured at 1.69 / 1.87 mean luma difference, §13 there).

## 1. Goal

Replace the ffmpeg assembly stage (`src/media/assemble.ts`, ASS captions) with a React/Remotion render
engine, without losing any Phase 1 guarantee:

1. Total length is exactly `Σ frames_i` frames (cumulative rounding of audio durations).
2. Audio and video stream durations within 1 frame.
3. Continuity seams stay pixel-faithful hard cuts.
4. Captions follow the narration (cumulative audio starts), independent of visuals.

New capabilities: Mode 2 Ken Burns in CSS, overlay transitions at cuts, three data-driven caption styles,
a BGM ducking curve computed from speech intervals, and a free `rerender` command.

### Non-goals (2.1)

SFX track, hook layer, brand kit/logo/brand fonts/intro-outro (2.3); LLM schema additions, per-scene
LLM transitions, style presets (2.2); Remotion Lambda, BullMQ/queues, web UI (later phases); keeping an
ffmpeg renderer as a fallback.

## 2. Decisions

| Topic | Decision |
|---|---|
| Engine | Remotion 4.x (`remotion`, `@remotion/bundler`, `@remotion/renderer`, `@remotion/captions`, `@remotion/fonts`, `@remotion/layout-utils`), React 19. License: free tier (≤ 3 people); revisit before the Phase 3 SaaS launch. |
| Clip timing | ffmpeg `fit` stays for **Mode 1** (seam frames depend on its exact filters); Remotion plays fitted clips 1:1. **Mode 2** is animated in Remotion (CSS Ken Burns); no Mode 2 mp4 is rendered any more. |
| Transitions | Overlay only, at `cut` boundaries, never moving audio; `continue` seams are always hard cuts. |
| Audio | Mixed in the composition (narration + BGM with a precomputed duck curve); ffmpeg loudness pass afterwards with `-c:v copy`. |
| Old engine | Removed (`media/assemble.ts` and ASS caption code deleted with their tests). |
| Free re-styling | `flowchain rerender <runId>` re-runs only the render stage with new style options ($0). |

## 3. Architecture

### 3.1 Data contract

The pipeline never touches React. A pure function `buildRenderProps(manifest, opts) → RenderProps` produces
one JSON object (zod-validated) that is the composition's only input. The same object can later drive the
Phase 3 browser preview (Remotion Player).

```ts
const Transition = z.enum(["cut", "fade", "dissolve", "blur", "zoom", "glitch"]);
const CaptionStyleName = z.enum(["hormozi", "mrbeast", "minimalist"]);

const RenderProps = z.object({
  fps: z.number().int(), width: z.number().int(), height: z.number().int(),
  totalFrames: z.number().int(),                       // = Σ scene.frames
  scenes: z.array(z.discriminatedUnion("kind", [
    z.object({ kind: z.literal("video"), src: z.string(), from: z.number().int(), frames: z.number().int() }),
    z.object({ kind: z.literal("still"), src: z.string(), camera: Camera,
               from: z.number().int(), frames: z.number().int() }),
  ])),
  boundaries: z.array(z.object({                        // one per scene start after scene 1
    frame: z.number().int(), kind: z.enum(["seam", "cut"]),
    transition: Transition, halfWindow: z.number().int(), // 0 for seams and for "cut"
  })),
  captions: z.object({ style: CaptionStyle, bottomPct: z.number(),    // bottomPct: 30 (9:16) / 12 (16:9)
                       pages: z.array(Page) }),                       // Page = TikTokPage from @remotion/captions
  audio: z.object({
    narration: z.string(),
    bgm: z.object({ src: z.string(), gain: z.number(), duckTo: z.number(), rampFrames: z.number().int(),
                    fadeOutFrames: z.number().int() }).nullable(),
    speech: z.array(z.object({ from: z.number().int(), to: z.number().int() })), // frames, merged + padded
  }),
});
```

All `src` values are paths relative to the render staging folder (§6.1), resolved with `staticFile()`.

### 3.2 Stage changes

| Stage | 2.1 behaviour |
|---|---|
| `script`, `tts`, `silence`, `keyframes` | unchanged |
| `clips` | Mode 1 unchanged (queue jobs, seam frames). `appliesTo` = Mode 1 scenes only. |
| `fit` | `appliesTo` = Mode 1 scenes only; same ffmpeg filters (seam frames depend on them). |
| `captions` | writes `captions.json`: `Caption[]` (`@remotion/captions`) from global word timings, `pageBreakAfter` set after `. , ! ? ; :` or every `maxWordsPerPage` words of the run's caption style. |
| `assemble` → **`render`** | `buildRenderProps` → Remotion render → ffmpeg loudness pass → `final.mp4`; writes `chain.png`. |

`StageName` replaces `assemble` with `render`. Stage order: `script, tts, silence, keyframes, clips, fit,
captions, render`.

### 3.3 Manifest v2

- `schemaVersion: 2`. `loadManifest` rejects other versions with: "run <id> was created by an older
  flowchain (schema 1); start a new run" (only two Phase 1 smoke runs exist; no migration).
- `request.render = { captionStyle: CaptionStyleName = "hormozi", transition: Transition = "fade",
  bgmGain: number(0..1) = 0.35 }`. Frozen per run; changed only by `rerender`.
- Mode 2 scenes have no `clip` and no `fitted` record.
- `final = { path, duration, chain }` (`captions` field dropped; `captions.json` is a regular stage output).

### 3.4 Module layout

```
src/media/remotion/
  index.ts            registerRoot(Root)                      (bundle entry point)
  Root.tsx            <Composition id="FlowchainVideo"> with calculateMetadata from props
  Video.tsx           layer stack
  layers/SceneLayer.tsx  (also holds the Ken Burns still)  layers/TransitionLayer.tsx
  layers/Captions.tsx    layers/AudioLayer.tsx
  props.ts            RenderProps / CaptionStyle zod schemas (shared by Node and React)
  styles.ts           CAPTION_STYLES: Record<CaptionStyleName, CaptionStyle>
  timeline.ts         pure: boundaries, transition windows, Ken Burns transforms, duck curve, active token
  render.ts           Node: stage public dir → bundle → selectComposition → renderMedia
src/media/audio.ts    concatAudio (moved from assemble.ts), loudnessPass
src/stages/render.ts  the render stage (replaces stages/assemble.ts)
src/stages/build-render-props.ts  pure manifest → RenderProps
```

`media/remotion/*` and `timeline.ts` know nothing about the manifest (Phase 1 dependency rule holds);
`build-render-props.ts` is the only bridge.

## 4. Composition

Layer stack, bottom to top: `SceneLayer`, `TransitionLayer`, `Captions`, *(reserved for 2.3:
`HookLayer`, `BrandLayer`)*, `AudioLayer` (no picture).

### 4.1 SceneLayer

Each scene is `<Sequence from={from} durationInFrames={frames}>`.

- **video (Mode 1):** `<OffthreadVideo muted src>` of the fitted clip. The clip is exactly `frames` frames at
  the output fps, so composition frame `from + j` shows clip frame `j` (no retiming).
- **still (Mode 2):** the Ken Burns still (a component inside `layers/SceneLayer.tsx`): an `<Img>` with `object-fit: cover` and a CSS transform. Progress
  `p = ease(frame / max(frames − 1, 1))`, `ease` = sine in-out. Cameras keep their Phase 1 meaning:
  `zoom_in` scale 1.00→1.15, `zoom_out` 1.15→1.00 (centred); `pan_left|right|up|down` at fixed scale 1.15,
  translating from one edge of the overscan to the other. Transforms are computed by a pure function in
  `timeline.ts` (unit-tested), the component only applies them.

### 4.2 Boundaries and transitions

For each scene `k ≥ 1` starting at frame `b = scenes[k].from`:

- `kind = "seam"` iff scene `k` is Mode 1 and does not need its own keyframe (it continues from the seam
  frame of scene `k − 1`); otherwise `kind = "cut"`.
- Seams always get `transition: "cut"`, `halfWindow: 0`. Cuts get `request.render.transition`.
- `halfWindow h = min(5, floor(frames_{k−1} / 2), floor(frames_k / 2))` for transitions other than `cut`
  (`glitch` uses h = 3).

**TransitionLayer** renders nothing outside windows. Inside `[b − h, b + h)` it draws, over SceneLayer:
**A** = scene `k − 1` (playing until `b`, then held on its last frame with `<Freeze>`) and **B** = scene `k`
(held on its first frame until `b`, then playing). With `q = (f − (b − h)) / 2h`:

| transition | effect |
|---|---|
| `cut` | none |
| `fade` | B opacity `q` over A |
| `dissolve` | fade plus blur on both peaking at 6 px at `q = 0.5` |
| `blur` | A blurs 0 → 20 px until `b`; B from 20 → 0 px after `b`. With `local = f − (b − h)`: A blurs `20·(local+1)/h`, B blurs `20·(2h−1−local)/h` |
| `zoom` | A scales 1 → 1.25 and fades out; B scales 1.25 → 1 |
| `glitch` | hard switch at `b`; frames `b − 1 … b + 1` get RGB channel offsets and horizontal slice shifts from a PRNG seeded with the boundary index (identical across renders) |

No transition changes `totalFrames`, any `from`, the audio, or captions.

### 4.3 Captions

- Pages come from `createTikTokStyleCaptions({ captions, combineTokensWithinMilliseconds: 1500 })` over
  `captions.json`; `pageBreakAfter` (set by the captions stage) gives Phase 1's paging, and a page also ends
  once it spans more than 1.5 s. The last caption never carries `pageBreakAfter` (the library would leave that
  page's duration at `Infinity`), and any non-finite duration is replaced by the last token's end.
- A page is visible from its `startMs` until the next page's `startMs` (or `startMs + durationMs` for the
  last). The active token is the last one with `fromMs ≤ t` (`t = frame / fps · 1000`): a word stays active until the next one starts, so nothing flickers in the gaps between words.
- One `<Captions>` component renders a `CaptionStyle` record (styles are data, so 2.2 presets and 2.3 brand
  kits only override fields):

```ts
const CaptionStyle = z.object({
  font: z.object({ family: z.string(), file: z.string(), weight: z.number() }), // file under assets/fonts
  textCase: z.enum(["upper", "none"]),
  sizePctOfShortSide: z.number(),          // % of the frame's short side: 1080 px for 9:16 and 16:9 alike
  color: z.string(), activeColor: z.string(), inactiveOpacity: z.number(),
  stroke: z.object({ color: z.string(), pctOfSize: z.number() }).nullable(), // painted under the fill
  shadow: z.string().nullable(),
  maxWordsPerPage: z.number().int(), activeAnim: z.enum(["none", "pop", "fade"]),
});
// Placement (bottomPct) depends on the aspect ratio, not the style, so it lives in RenderProps.captions.
```

| style | font (bundled, license file alongside) | look | words/page | active word |
|---|---|---|---|---|
| `hormozi` (default) | Montserrat ExtraBold (OFL, already bundled) | uppercase, white, 7.5 % size, black stroke 12 % (≈ 6 % visible) | 3 | `#FFE500`, no animation |
| `mrbeast` | Luckiest Guy (Apache 2.0) | uppercase, white, 8.5 % size, black stroke 18 % + drop shadow | 2 | `#3CFF5A`, pop: scale 1.15 → 1 over 4 frames |
| `minimalist` | Inter SemiBold (OFL) | sentence case, white, 5.5 % size, soft shadow, no stroke | 6 | fades 0.6 → 1 over 4 frames, others 0.6 |

- Fonts load with `@remotion/fonts` `loadFont()` from the staging folder under a `delayRender` handle that is
  released only in an effect after the re-render with the font has committed (releasing it in the load
  callback let the first captured frame of a render tab miss its caption); a failed load calls `cancelRender`.
  No system fonts.
- Placement: centred horizontally, positioned with CSS `bottom: <bottomPct>%` (a percentage of the frame
  height; padding percentages would use the width), `bottomPct` = 30 % (9:16, clear of TikTok/Shorts UI) or
  12 % (16:9). A page wider than 90 % of the frame is scaled down with `@remotion/layout-utils` `fitText`.
- The space before a word is rendered outside the word's (possibly scaled) box, so a popping word never
  swallows it; pop styles add 0.08 em of side margin to every word.

### 4.4 Audio

- **Narration:** one `<Audio src={narration}>` from frame 0. `narration.wav` is the sample-exact
  concatenation of the trimmed scene WAVs (per-scene `<Audio>` would snap each start to a frame and click).
- **BGM** (only with `--bgm`): `<Audio loop loopVolumeCurveBehavior="extend" src volume={(f) => gain · duck(f) · fadeOut(f)}>`.
  - `loopVolumeCurveBehavior="extend"` is required: Remotion's default (`"repeat"`) restarts the frame passed to `volume` on every loop, so `duck` and `fadeOut` (absolute video frames) would be evaluated against the wrong frame whenever the BGM file is shorter than the video.
  - `speech`: intervals from global word timings, gaps < 0.35 s merged, padded by 0.1 s, in frames.
  - `duck(f)` = `duckTo` (0.18) inside speech, 1.0 outside, 6-frame linear ramps at every edge.
  - `fadeOut(f)` = linear 1 → 0 over the last 30 frames.
  - `duck` and `fadeOut` are pure functions in `timeline.ts`; the component only calls them.
- **Loudness pass** (ffmpeg, after Remotion): `-c:v copy`, audio
  `loudnorm=I=-14:TP=-1.5:LRA=11,aresample=48000,apad,atrim=end=<totalFrames/fps>`, AAC 192k,
  `+faststart` → `final.mp4`. Pinning the audio length keeps A/V within 1 frame regardless of encoder delay.

## 5. chain.png

Rows in scene order, columns = (first, last):
- Mode 1: first frame of the raw clip, last frame of the fitted clip (as Phase 1).
- Mode 2: the keyframe in both cells (the scene is a still).

## 6. Node-side rendering (`media/remotion/render.ts`)

### 6.1 Staging

`<runDir>/render/public/` is recreated per render and filled with **hard links** (falling back to copies
across filesystems) to every file the props reference, plus the caption style's font file. Props paths are
relative to it. The run folder itself is never the public dir (no half-written files get bundled). The whole
`<runDir>/render/` folder (staged links and the bundle, which copies the public files) is deleted after a
successful render.

### 6.2 Bundle and render

1. `bundle({ entryPoint: src/media/remotion/index.ts, publicDir: <staging>, outDir: <runDir>/render/bundle,
   enableCaching: true, webpackOverride })` — the override adds `resolve.extensionAlias { ".js": [".ts",
   ".tsx", ".js"] }`, because the codebase imports TypeScript files with `.js` extensions (NodeNext).
2. `selectComposition({ id: "FlowchainVideo", inputProps })`.
3. `renderMedia({ codec: "h264", crf: 18, pixelFormat: "yuv420p", x264Preset: "medium", audioCodec: "aac",
   audioBitrate: "192k", enforceAudioTrack: true, imageFormat: "jpeg", jpegQuality: 90, concurrency,
   inputProps, outputLocation: <runDir>/video.mp4, onProgress })` — progress logged every 10 %.
4. Loudness pass → `final.mp4`, then `chain.png`. The pass writes `final.mp4.tmp.mp4` in the run folder and renames it over `final.mp4` only on success, so a failed pass never destroys the previous final video.

Exact option names are verified against the installed Remotion version during planning.

### 6.3 Browser

Remotion renders with Chrome Headless Shell. `doctor` adds a check that calls `ensureBrowser()` (one-time
≈ 100 MB download into Remotion's cache) and reports success, so a paid run never stalls on it.

### 6.4 Render cache key

`inputHash(render) = hash({ props: RenderProps JSON, files: sha256 of every referenced file,
engine: hash of all files under src/media/remotion/, font: sha256 of the style's font file,
remotion: Remotion's `VERSION`, loudness: the loudness-pass ffmpeg arguments })`. The loudness arguments come from the same function the pass runs (`loudnessPassArgs`), so key and behaviour cannot drift.
Changing composition code, a style, a font, the BGM or any upstream media re-renders; nothing else does.

### 6.5 Performance

Measured while prototyping (Apple Silicon, Remotion 4.0.532, default concurrency): re-rendering the live
smoke run (16 s, 479 frames, 1080×1920, three real Kling clips) took **92 s** wall time for the whole render
stage including bundling; a 90-frame 180×320 test render takes ≈ 4.5 s once the webpack cache is warm. The
first ever render also downloads Chrome Headless Shell (93.5 MB). The rendered video measured −14.8 LUFS,
A/V 15.9667 s vs 15.966 s, and seam jumps of 1.83 / 2.14 mean luma (the Phase 1 ffmpeg engine: 1.69 / 1.87).
`--render-concurrency <n>` overrides Remotion's default concurrency.

## 7. CLI

| flag (on `run`) | default | stored |
|---|---|---|
| `--caption-style hormozi\|mrbeast\|minimalist` | `hormozi` | `request.render.captionStyle` |
| `--transition cut\|fade\|dissolve\|blur\|zoom\|glitch` | `fade` | `request.render.transition` |
| `--bgm <file>` (exists) | none | `request.bgm` |
| `--bgm-gain <0–1>` | 0.35 | `request.render.bgmGain` |
| `--render-concurrency <n>` | Remotion default | not stored (speed only) |

**`flowchain rerender <runId> [--caption-style …] [--transition …] [--bgm-gain …] [--render-concurrency n]`**
- Requires every stage up to and including `fit` (all paid work) to be `done` and fresh for the current
  inputs; otherwise fails with "run <id> is not complete; use resume".
- Updates `request.render` with the given options, saves the manifest, and runs the pipeline under the run
  lock. Only `render` (and `captions` when `maxWordsPerPage` changes with the style) re-run; both are free,
  so the ledger does not change.
- No confirmation prompt (no paid work can be planned); if the plan contains any paid item the command
  aborts instead.

## 8. Testing

**Pure units (no Chrome):** `buildRenderProps` (scene kinds, `from`/`frames`, Σ = `totalFrames`, seam vs cut
classification), transition windows (shrinking, never on seams, inside the timeline), Ken Burns transforms
for all six cameras at p = 0 / 0.5 / 1, caption page visibility and active-token lookup, duck curve (levels,
ramps, merged gaps, fade-out), `CaptionStyle`/`RenderProps` schema validation, `rerender` option handling
and its "no paid work" guard, manifest v1 rejection.

**Remotion render tests (real Chrome, 180×320, fake providers):**
1. Full pipeline, modes `1, 2, 1, 1` with shots `cut, cut, cut, continue` (a scene after a Mode 2 scene always
   gets its own keyframe, so the seam needs two Mode 1 scenes in a row): frame count = `totalFrames`; A/V
   within 1 frame; at the seam the frames on both sides in `final.mp4` are within an H.264 tolerance (mean luma
   diff < 2, top half, clear of captions) of the fitted clips' frames; `chain.png` has 4 rows.
2. Transition, rendered directly from props: a red → blue `fade` is pure red before the window, half-and-half
   at the boundary and pure blue after it; a 7-scene render with all six transitions keeps every scene's own
   colour mid-scene.
3. Every caption style renders visible text in the caption band.
4. BGM ducking: with a silent narration and a tone as BGM, the mean volume (ffmpeg `volumedetect`) between
   speech ranges is > 10 dB above the volume inside them.
5. `rerender` to `mrbeast` + `zoom` plans only `captions` and `render`, changes `final.mp4`, leaves the ledger and
   every paid record unchanged.

Unchanged: seam-image identity, paid-job, resume and reroll tests. `npm run smoke` now renders through
Remotion.

## 9. Definition of Done

1. `npm run smoke` produces `final.mp4` through Remotion with invariants 1–4 of §1 holding and two seams that
   remain hard cuts.
2. All three caption styles and all six transitions render; BGM ducks under speech.
3. `rerender` switches the look of an existing run at $0.
4. `doctor` checks the Remotion browser. `npm test` and `npm run typecheck` pass.
5. Measured render time for the smoke video is recorded in §6.5.

## 10. Changes outside the engine

- `doctor` drops the libass, `zoompan`, `ass` and `sidechaincompress` checks (no longer used), checks all three
  caption fonts, and checks Remotion's browser (`ensureBrowser()`).
- `createManifest` validates its request with `RunRequest.parse` (filling `render` defaults), which also closes
  the Phase 1 note that it accepted invalid requests.
- The render cache key covers the caption font and the composition source, closing the Phase 1 note that the
  assemble stage ignored font changes.

## 11. Risks and open items

- **Remotion license:** free tier assumed (≤ 3 people); must be revisited before a commercial SaaS launch.
- **Render time:** Chrome-based rendering is slower than ffmpeg concat; acceptable for the CLI, revisit with
  Lambda in a later phase.
- **Font licenses:** Luckiest Guy (Apache 2.0) and Inter (OFL) are redistributable; license files ship next
  to the fonts. Download sources are pinned in the plan.
- **Test runtime:** render tests need Chrome Headless Shell (downloaded once) and add tens of seconds to
  `npm test`.
