# Phase 2.2 — Content Intelligence & Style Presets: Design Spec

- **Date:** 2026-10-04
- **Status:** Approved (brainstorming sections 1–4)
- **Scope:** Sub-project 2.2 of Phase 2. Builds on Phase 1
  (`2026-10-02-phase1-cli-poc-design.md`) and 2.1 (`2026-10-03-phase2.1-remotion-render-engine-design.md`).
  2.3 (hook, auto-SFX, brand kit, BGM duck level, fade-end polish) is out of scope.

## 1. Goal

Let the script drive more of the video, while keeping costs predictable and every existing run working:

1. Gemini rates each scene's **action level** and suggests a **transition** for each cut.
2. `--mode auto` resolves each scene's mode from the action levels **and the run's budget** (Smart Hybrid Mode Recommender).
3. Six **style presets** wrap every Flux and Kling prompt and bring their own caption look; Gemini picks one when the
   user does not.

### Non-goals

`suggestedMode` (the mode policy uses `actionLevel` only), per-preset Kling negative prompts, hook/SFX/brand layers,
BGM duck level and fade-end polish (2.3), a manifest schema bump, migrating Phase 1 (schema 1) runs.

## 2. Decisions

| Topic | Decision |
|---|---|
| Mode policy | Deterministic rules on `actionLevel`: high → Mode 1, low → Mode 2, medium → Mode 1 while the budget allows |
| Where modes resolve | A new free, cached, run-level `modes` stage after `silence` (exact 5 s / 10 s Kling buckets known) |
| Transitions | `render.transition` gains `"auto"` (default): each cut uses the incoming scene's `suggestedTransition`; an explicit `--transition X` applies X to every cut; seams stay hard cuts |
| Presets and captions | Each preset carries a full `CaptionStyle` with a bundled OFL font (3 new: Cinzel, Orbitron, Bangers); `render.captionStyle` gains `"preset"` (default); an explicit caption style overrides it |
| Preset source | `--style X` forces X; otherwise Gemini picks `stylePreset` for the topic |
| Preset vs styleBible | With a preset in effect the preset leads: `styleBible.artStyle` is replaced by the preset's `artStyle`; Gemini still writes characters, palette and scene prompts |
| Prompt wording | Presets describe visual qualities only — never named studios, artists or products |
| Compatibility | Manifest stays `schemaVersion: 2`; every new field is optional when loaded |

## 3. Data Model

### 3.1 Gemini's answer (`LlmScript`, sent as the response schema — every field required)

```ts
const ActionLevel = z.enum(["high", "medium", "low"]);
const SuggestedTransition = z.enum(["cut", "fade", "dissolve", "zoom_transition"]);
const PresetName = z.enum(["cinematic_history", "anime", "cyberpunk", "dark_fantasy", "photorealistic_8k", "3d_render"]);

LlmSceneSpec = SceneSpec.extend({ actionLevel: ActionLevel, suggestedTransition: SuggestedTransition });
LlmScript = Script.extend({ stylePreset: PresetName, scenes: z.array(LlmSceneSpec).min(1).max(12) });
```

`validateScript` validates against `LlmScript`; the existing post-checks (scene count, ≤ 22 words) still apply.

### 3.2 Stored script (`Script` in the manifest)

Same fields, but `actionLevel`, `suggestedTransition` and `stylePreset` are **optional**, so manifests written before
2.2 still parse. New runs always have them (the response schema requires them).

### 3.3 Run request

| Field | Change |
|---|---|
| `style?: PresetName` | new — from `--style`; absent ⇒ Gemini picks |
| `modes?: Mode[]` | now **optional** — absent ⇒ `--mode auto` (rules); `--modes` / `--mode 1\|2` fill it as before |
| `modeBudgetUsd?: number` | new — `--budget` (or `FLOWCHAIN_BUDGET_USD`) frozen at creation; required when `modes` is absent |
| `render.transition` | `Transition \| "auto"`, default `"auto"` |
| `render.captionStyle` | `CaptionStyleName \| "preset"`, default `"preset"` |

`createManifest` still lays out one `SceneState` per scene; with `auto`, every scene starts with the **provisional**
`mode: 1` (the most expensive assumption) until the `modes` stage runs.

### 3.4 Scene state

`SceneState.modeReason?: string` — written by the `modes` stage, shown by `status`.

### 3.5 Effective values (pure helpers)

- **Preset:** `request.style ?? script.stylePreset ?? null` (null only for pre-2.2 runs).
- **Caption style:** explicit name → `CAPTION_STYLES[name]`; `"preset"` → the preset's caption; `"preset"` without a
  preset → `CAPTION_STYLES.hormozi`.
- **Transition at a cut into scene k:** explicit → that transition; `"auto"` → `suggestedTransition` of scene k mapped
  (`zoom_transition → zoom`, others unchanged), falling back to `fade` when the field is missing. Seams are always `cut`
  with half-window 0 (2.1 rule unchanged).

## 4. Pipeline

`script → tts → silence → modes → keyframes → clips → fit → captions → render`

### 4.1 `modes` stage

- Run-level, free (`paid: false`), cached; `deps`: `script` and `silence` of every scene.
- Explicit runs (`request.modes` present): copies `request.modes` into `scenes[i].mode`, `modeReason = "explicit"`.
- Auto runs: calls `planModes` (§5) and writes `scenes[i].mode` and `modeReason`.
- Inputs (cache key): explicit modes or, for auto, every scene's `actionLevel` and `shot`, every scene's Kling bucket
  (`requestedSec` of its trimmed audio), narration lengths, the price table, `modeBudgetUsd`, the keyframe size.
- `keyframes`, `clips` and `render` list `{ stage: "modes" }` in `deps` **only for auto runs**, so explicit (and all
  pre-2.2) runs never price downstream work as dirty because of the new stage. Execution still decides by hash.

### 4.2 Script stage

- Sends `style` (if any) to Gemini; the prompt lists the presets with one-line descriptions and explains
  `actionLevel` and `suggestedTransition` (§6.2).
- After validation: `--shots` override (unchanged); `stylePreset := request.style` when given; with a preset in effect,
  `styleBible.artStyle := preset.artStyle`.
- Cache inputs add `style`.

### 4.3 Cost checkpoints

- Checkpoint 1 (before `script`): auto runs are estimated as all Mode 1 (provisional) — pessimistic.
- Checkpoint 2 moves to just before `keyframes` as today; it now runs after `modes`, so it is exact.
- Budget confirmation keeps using the invocation's `--budget`; the mode rules use the frozen `modeBudgetUsd`.

## 5. Mode Rules (`src/modes.ts`)

```ts
type PlanModesInput = {
  scenes: Array<{ actionLevel: ActionLevel; shot: Shot; requestedSec: 5 | 10; narrationChars: number }>;
  prices: Prices; keyframeSize: Size; budgetUsd: number;
};
type PlanModesResult = { modes: Mode[]; reasons: string[]; estimatedUsd: number };
planModes(input): PlanModesResult   // pure
```

1. Start: `high` → 1, `medium` → 1, `low` → 2.
2. `cost(modes)` = `scriptCost` + Σ `ttsCost(narrationChars)` + Σ over scenes that need a keyframe under `modes` of
   `imageCost(keyframeSize)` + Σ over Mode 1 scenes of `videoCost(requestedSec)`. A scene needs a keyframe iff it is
   scene 1, Mode 2, preceded by a Mode 2 scene, or its shot is `cut` (Phase 1 rule, evaluated on candidate modes).
3. While `cost > budgetUsd` and a `medium` scene is still Mode 1: switch the medium Mode 1 scene with the **largest
   saving** (`cost(before) − cost(after)`, which includes keyframes the switch adds) to Mode 2; ties go to the **later**
   scene. Re-cost and repeat.
4. If still over budget with only `high` scenes left, they stay Mode 1 (the checkpoint-2 prompt then asks as usual).
5. Reasons: `"auto: high action"`, `"auto: medium action"`, `"auto: medium action → Mode 2 to fit $<budget>"`
   (budget with 2 decimals), `"auto: low action"`.

Continuity follows automatically: a `continue` scene whose own or previous mode is 2 becomes a cut through the
keyframe rule; its script `shot` is never rewritten.

## 6. Style Presets (`src/presets.ts`)

### 6.1 Record

```ts
type StylePreset = {
  name: PresetName;
  description: string;   // one line for Gemini
  artStyle: string;      // replaces styleBible.artStyle
  imagePrefix: string; imageSuffix: string;
  motionKeywords: string;
  caption: CaptionStyle;  // same record type as hormozi/mrbeast/minimalist (2.1 §4.3)
};
export const PRESETS: Record<PresetName, StylePreset>;
```

Prompt composition with a preset in effect:

```
image  = "{imagePrefix}. {characters}. Palette: {palette}. {scene.imagePrompt}. {imageSuffix}"
motion = "{scene.motionPrompt}. {motionKeywords}. Keep style consistent: {artStyle}. {characters}."
```

Without a preset (pre-2.2 runs) the Phase 1 wording is unchanged, so their cache keys and paid work stay valid.

### 6.2 Gemini instructions (added to the prompt)

- The six presets with descriptions; "set `stylePreset` to the best fit for the topic" or, with `--style`,
  "use exactly X".
- "Do not describe the art style in imagePrompt; it is added automatically."
- `actionLevel`: high = fast or complex motion worth real video; medium = some motion; low = still, contemplative or
  text-like moments.
- `suggestedTransition` (how the cut **into** this scene should feel): `cut` punchy/continuous energy, `fade` /
  `dissolve` time passing or mood shift, `zoom_transition` an energetic jump. Scene 1's value is ignored.

### 6.3 The six presets

| Preset | Prompt flavour | Caption font | Active | Look |
|---|---|---|---|---|
| `cinematic_history` | 35 mm film still, natural light, period-accurate costumes, film grain, muted earth tones | Cinzel 700 (new) | `#E8C468` | white, black stroke, 3 words |
| `anime` | anime key visual, cel shading, clean line art, painted background, vibrant colours | Bangers (new) | `#FF4FA3` | white, thick stroke, pop, 2 words |
| `cyberpunk` | neon-lit night city, rain reflections, holographic signs, teal/magenta haze | Orbitron 700 (new) | `#FF2BD6` | white, cyan glow shadow, 3 words |
| `dark_fantasy` | gothic oil painting, candlelight and deep shadows, crimson accents | Cinzel 700 | `#C0182B` | bone `#EDE6D6`, stroke, fade, 3 words |
| `photorealistic_8k` | photorealistic, full-frame camera, natural light, true-to-life colour | Inter SemiBold | `#FFFFFF` | minimalist look, 6 words |
| `3d_render` | stylized 3D render, soft global illumination, clay-like materials, playful colours | Montserrat ExtraBold | `#FF9F1C` | white, stroke, pop, 3 words |

Exact strings and numbers live in `src/presets.ts`.

### 6.4 Fonts

New bundled fonts with their licenses in `assets/fonts/`: Cinzel and Orbitron (variable `wght`, Google Fonts `ofl/`),
Bangers (static). `doctor` checks the font of every caption style **and** every preset. Variable fonts must render at
the requested weight in Chrome (verified by a render test).

## 7. CLI

| Command | Change |
|---|---|
| `run` | `--style <preset>`; `--mode auto` (default) = the rules; `--transition auto\|cut\|fade\|dissolve\|blur\|zoom\|glitch` (default auto); `--caption-style preset\|hormozi\|mrbeast\|minimalist` (default preset); `--budget` is also frozen as `modeBudgetUsd` for auto runs |
| `rerender` | `--transition` and `--caption-style` accept `auto` / `preset` |
| `status` | preset and its source (`cyberpunk (by Gemini)` / `cyberpunk (--style)`); each scene's mode with its reason |
| npm | new `smoke:auto` = `run --topic … --scenes 4 --mode auto --style cyberpunk --bgm assets/music/example-bed.mp3` |

`rerender`'s free-stage list becomes `modes`, `captions`, `render` (all free); any paid item still refuses.

## 8. Testing (offline)

- **Unit:** `planModes` table (initial mapping; downgrade order by saving; later-scene tie; chain-break penalty; highs
  kept over budget; reasons text); preset prompt composition; caption-style precedence; transition resolution (auto
  per cut, override, seams, missing field); Gemini prompt lists presets / `--style`; script stage enforces `--style`
  and the preset `artStyle`; `LlmScript` requires the new fields while the stored `Script` does not; a pre-2.2
  manifest loads and its rerender plan contains only free stages.
- **Stages (fakes):** an auto run with `[high, medium, low]` gets modes `1,1,2` and reasons; a tight budget downgrades
  the expected medium scene; prompts sent to the fake image/video providers contain the preset's prefix, suffix and
  motion keywords; explicit-mode runs keep `modeReason "explicit"`.
- **Chrome:** all six preset caption looks render visible text, including the variable-weight fonts.
- **Live (paid, with the user's approval):** `npm run smoke:auto`.

## 9. Definition of Done

1. `npm test` and `npm run typecheck` pass; existing runs (2.1 live run) still load and `rerender` for free.
2. `--mode auto` resolves modes per §5 with visible reasons; checkpoint 2 is exact.
3. Presets wrap prompts, set captions, and Gemini picks one when `--style` is absent.
4. Cuts use Gemini's suggested transitions unless `--transition` is given.
5. A live `smoke:auto` run (after approval) is recorded in this spec.
